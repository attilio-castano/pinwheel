## Target and continuation rule

Pursue a complete digital session: cold initialization, source program upload,
COMMIT, SPI/I²C execution, retained result read, RELEASE and another transfer.
The queue is:

1. Reusable source/packed-Reactive refinement for all eight buffered operations
   under independently checked static encoding/layout certificates.
2. Initialized reactive I²C source execution through actual digital SRAM,
   arbitrary raw-input histories and finite prefixes, complete/fault/timeout
   outcomes and partial TX/RX diagnostics.
3. Repeated upload/commit/START/read/RELEASE/reuse/reset sessions with actual
   finite-counter and identity semantics, including rejected commands.
4. Sampled serial request delivery and frozen receipt composition with an actual
   typed frontend/SRAM product recurrence. The engine advances on every sample.

A completed intermediate item starts the next item. Stop early only if the
entire queue and verification close. Then I²C duration/budget parameterization
is the next extension. At the deadline preserve partial results and name all
unclosed statements; an intermediate theorem is not complete-session proof.

## Contracts

The physical target has 64 stored rows and 16 branch descriptors. A source
program's larger syntax/virtual bounds alone do not prove representability.
Static certificates may cover encoding, finite geometry, loop and endpoint
coordinates; they must not assume step, trace or observation agreement.

START source state must be obtained from admitted operands. Arbitrary scratch,
WAIT deadline priority, CHECKED terminal capture before branch, QUALIFY reset,
self-entry and consume-before-append fault ordering are explicit obligations.
Stopped samplers require abstraction; later START needs a causal new seed.

Warm reset preserves the hardware transfer counter while invalidating image and
ownership. Counters saturate. Cold reset establishes a new software epoch;
the existing wire format has no epoch field and does not promise replay
authentication across reset. There is no separate image-preserving abort.

Serial requests span 160 sampled bits and responses 192. Request close,
dispatch with rejection latching, and response snapshot occur on distinct core
edges. Transport cannot be compressed to one engine step or a START receipt
treated as final completion.

## Work and validation

Parallel owners develop generic phase/source equations, I²C initialized image
certificates, and serial-model/package correspondence. Main integration owns
static layout/encoding, the execution relation, lifecycle composition and final
theorems. Shared dependencies are announced only after their `.olean` checks.

Kernel-check active proofs incrementally, with standard axioms only. Use
focused independent executions and distinguishing mutation controls at each
milestone. Reserve the full foundation gate for final integration. Commit
validated stages and leave a report with source-bound logs, exact accepted
statements, counterexamples and remaining gaps.

RTL, ABI, circuit/source semantics and physical evidence are frozen. Any
semantic mismatch is reported explicitly before a behavioral change is made.
No CAD, push, PR, external publication or paid service is authorized.
