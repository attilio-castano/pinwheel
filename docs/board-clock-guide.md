# Board clock guide

Pinwheel's programs count time in core clocks, so the clock a board supplies
decides what each example does on the wire. This page lists, for two
candidate board clocks, the setting to use for each example and what it
achieves. The 4 MHz column matches the bring-up fixtures; 50 MHz is the
20 ns clock the layout was built for, which is a design target rather than a
qualified operating clock.

Every number below is computed in Lean from the program clock contracts and
exported through the [chip manifest](../Pinwheel/Hardware/StreamingReady/ChipManifest.lean)
(`guide`, with the verdicts checked by `guide_usable`). The table is generated
by `scripts/board_clock_guide.py` and checked by `scripts/check-chip-manifest.py`.

## What each row means

- **UART receive** ([contract](../Pinwheel/Program/StreamingUARTClock.lean)):
  one bit lasts `4 × quarter_cycles` core clocks. A frame is received when each
  of the receiver's sample points, which may land up to one core period late,
  stays inside its bit (`received`). That allows roughly −5 % to +5.5 % of
  baud mismatch. `quarter_cycles` is at most 128, so slow baud rates need a
  slow core clock.
- **SPI and JTAG** ([contract](../Pinwheel/Program/StreamingSerialClock.lean)):
  the bit clock idles for at least `half_cycles + 1` core periods and is
  active for `half_cycles` (`cell_window`). Data in is sampled three core
  periods before each leading edge (`capture_sample`), so the peer must drive
  its output within `half_cycles − 2` periods of the trailing edge. The peer
  must also accept the listed bit clock rate.
- **I²C** ([waveforms](../Pinwheel/Program/StreamingI2CWaveform.lean),
  [stretching](../Pinwheel/Program/StreamingI2CClock.lean)): the listed modes
  are those whose SCL LOW, SCL HIGH, SDA setup, SCL period, START hold and
  STOP setup minimums the profile meets (`Meets`, `start_window`,
  `stop_window`). The controller's data hold time is zero, and a target may
  stretch SCL for at most the listed number of core clocks before the
  transfer faults. Bus-free time between transactions depends on when the
  host starts the next one. The bring-up fixture emits the Fast and standard
  rows with `--i2c-mode fast` and `--i2c-mode standard`, and its `simulate`
  command runs them through the public-pin RTL model with the same option.
  These rows use the largest poll budget (`wait_budget=255`), so a target may
  stretch for 252 core clocks: in simulation, a target whose STOP stretch grows
  with the slower SCL phases faulted the transfer at the default budget.
- **CAN, PS/2 and Ethernet** use fixed images proved at one clock: 4 MHz for
  CAN and PS/2, and 60 MHz locked to the PHY for Ethernet, which is above the
  layout target. See [streaming-ready.md](protocols/streaming-ready.md).

## Limits

The contracts treat each pin observation as one core period and each sample
as the bus level at its clock. Pad delays, board wiring, rise times and the
input synchronizer's analog behavior are outside them, so a real board needs
margin beyond these numbers. The 50 MHz rows assume the layout meets timing
at 20 ns, which is not yet qualified.
